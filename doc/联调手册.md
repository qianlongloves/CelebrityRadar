## 二、云 DB 建表清单（8 张，主键列名一律为 `id`）

| 表 | 字段（类型） | 说明 |
|---|---|---|
| `users` | id(text PK) / nickname(text) / avatar_url(text) / settings(jsonb) / created_at(timestamptz) / **last_seen_at(timestamptz)** | Auth 登录后首次进入初始化。⚠ `last_seen_at` 是代码 upsert 的必填列（`utils/auth.ts`），漏建会导致登录初始化报「列不存在」 |
| `report_cache` | id(text PK) / report(jsonb) / generated_at(timestamptz) / state(text: building\|ready) / builder(text) / search_meta(jsonb) | **全局共享，需允许匿名读**（未登录/其他用户读 ready 行）；写权限需登录 |
| `feed_cache` | id(text PK) / items(jsonb) / fetched_at(timestamptz) | 搜索结果映射 |
| `refresh_quota` | id(text PK) / count(int) | id = `openid#yyyy-mm-dd` |
| `follows` | id(text PK) / openid(text, 建索引) / person_key(text) / name(text) / domain(text) / followed_at(timestamptz) | 关注列表 |
| `favorites` | id(text PK) / openid(text, 建索引) / type(text: quote\|report) / payload(jsonb) / person_key(text) / name(text) / created_at(timestamptz) | 收藏（id = openid#type#hash 防重） |
| `history` | id(text PK) / openid(text, 建索引) / person_key(text) / name(text) / ts(timestamptz) | 查询历史（保留 50 条） |
| `events` | id(text PK) / openid(text) / event(text) / person_key(text) / props(jsonb) / created_at(timestamptz) | 埋点 |

**权限（RLS）要点**：
- `report_cache`：`select` 允许匿名（共享缓存的核心设计）；`insert/update/delete` 仅登录用户
- 其余用户表：行级 `openid = auth.uid()`（等价）或 MVP 阶段登录可读写
- `.or()` 条件更新（缓存抢锁用）**需实测**：若控制台策略拦截 update 带 or 条件，需放宽 `report_cache` 的 update 权限到登录用户全量

## 三、验收用例操作手册（§5.4 逐条）

前置：微信开发者工具导入 `celebrity-radar/`，`public.ts` 已填真实云配置、8 表已建、§五 的素材方案已落地。

| # | 用例 | 操作 | 预期 |
|---|---|---|---|
| 1 | 消歧 | 搜「李娜」→ 出候选（体育/文娱等）+ 末位「都不是 TA」；选定一位 | `personKey=李娜#sports`；重复选定同一人 key 不变 |
| 2 | 缓存命中 | 设备 A 生成某名人报告后，24h 内再次进入 | 秒开，页头「生成于 xx 前 · 查看最新」；DB 无新增 report_generate 事件 |
| 3 | 缓存未命中 | 设备 A 查一个全新名人 | 报告各字段齐全；dynamics/sources 的 URL 全部能在搜索素材中找到；quotes.source 为素材 URL 或「据公开资料」 |
| 4 | 并发互斥 | A、B 两机同时进同一未缓存名人报告页 | 仅一方显示「正在生成」，另一方显示「排队等待」；最终两机看到同一份报告；DB 中该 personKey 只有 1 次 report_generate |
| 5 | 冷启动 | 分两支验：① **未配 key** —— 「我的 → 联网能力」点「清除」后，查一个从未生成过的名人；② **已配 key 但素材拉不到** —— 断网 / 填一个无效 key 后同样操作 | ① 「尚未配置联网能力」+「去配置」（点按跳「我的」页）；② 「暂无报告」+「刷新重试」。两支均无报错、无死循环 |
| 6 | 刷新配额 | 任一机连续下拉刷新关注流 11 次 | 第 11 次提示「今日刷新已达上限（10 次）」；次日（或改设备时间）恢复 |
| 7 | 敏感输入 | 搜索「国防部长」或任一敏感关键词 | 直接「暂不支持查询该人物」，网络面板无搜索/云请求 |
| 8 | 空结果 | 搜一个素材源搜不到内容的名人（或临时把搜索 query 改错） | 「暂无动态」态（`nonews`），与用例 5 的 `coldstart` 是两个不同引导态 |
| 9 | 错误态 | ① 断网生成 → 自动重试 2 次（1s/2s）后失败提示；② 令搜索配额耗尽/密钥失效触发 429 → 冷却提示「约 N 分钟后恢复」（冷却 10 分钟，storage 持久）；③ （模拟）LLM 输出非法 JSON 两次 → 降级纯文本报告（标题带「简版降级」） | 三条路径均有 UI 呈现，无白屏 |
| 10 | 免责与合规 | 检查报告页 / 主页 / 关注流 / 分享文案 / 我的页 | 均带「AI 生成，仅供参考」；隐私声明页可读；举报按钮拉起客服会话；「我的 → 清空我的数据」有入口（灭色警示 + 二次确认，确认后 toast 反馈结果） |
| 11 | 体积与埋点 | 构建产物统计 + events 表查询 | 主包 < 2MB 上限（当前 859KB，口径 = `dist/` 全量文件求和、项目无分包）；上述操作产生的 9 类事件均有落库 |

**指标出数口径**（上线首日）：缓存命中率 = `report_hit_cache / (report_hit_cache + report_generate)`；人均关注数从 `follows` / 活跃用户；留存从 `events` 首末次出现日期。

## 五、搜索素材来源：SDK 事实约束与三选项（**当前最大决策点**）

**SDK 实证（`@tencent-ai/workbuddy-cloud-sdk@0.1.3`）**：
- 云客户端只有 4 个模块：`auth` / `database` / `storage` / `llm`（`lib/miniprogram.d.ts` 中 `class` 的 4 个 readonly 属性）——**没有云函数 / 边缘函数调用通道**
- `llm` 模块**不含联网检索**（类型中仅有流式 chat 与 tools 声明，无 web search 能力）
- ⇒ 「云函数代持 Tavily key」**无法通过 SDK 直接实现**，需走下面的 A 方案（自建服务 + HTTP）

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A. 云托管自建服务 + HTTP**（能力已确认可用，**发版建议路径**） | 部署一个持 `BOCHA_API_KEY` 环境变量的服务，暴露 `POST /search`；前端 `utils/search.ts#fetchNews` 改走 `Taro.request(自建域名)` | 前端不持有密钥，可做限流/缓存 | 需写服务 + 部署 + 加合法域名；前端需改造 |
| **B. key 存云端表** | 把 key 放进一张登录可读的配置表，前端读后直连博查 | 实现最省 | key 对前端可见（抓包/反编译可得）⇒ **等同半公开**，只防「用户懒得注册」 |
| **C. 恢复本地 key 入口** ✅ **已落地 2026-10-05** | 「我的 → 联网能力」填两枚 key（仅存本机 storage），前端直连 `api.bochaai.com` | 零后端成本，立刻可用 | 用户需自己注册博查；发版审核对「让用户填第三方 key」不友好 |

**当前代码状态**：**方案 C 已落地** —— `pages/mine` 新增「联网能力」卡（博查 key + 大模型 key，页内 `Input` + 保存 / 清除 / 测试连通性），`pages/report` 的 `coldstart` 按「是否已配 key」分流引导（未配 ⇒ 「去配置」；已配 ⇒ 「刷新重试」）。填入有效 key 后报告即可真实生成。日后若转方案 A，只需替换 `utils/settings.ts` 的 `getBochaKey` / `getLlmKey` 两个取值点，UI 层零改动。

> ⚠ **口径校正**：本节早前版本通篇写 Tavily（`api.tavily.com` / `getTavilyKey()`），但 `utils/search.ts` **早已迁移到博查**（`https://api.bochaai.com/v1/web-search`、storage key `settings:bocha_api_key`），原因写在代码注释里 —— 博查是**国内备案域名**，可直接配进小程序 request 合法域名。**这次迁移此前未进任何文档**，本版一并校正。
