# 名人雷达 · MVP 开发计划

> 依据：《名人雷达_设计方案.md》v1.3（2026-10-04）
> 范围：MVP 三条主线（查报告 / 关注沉淀 / 账号设置），对应 §5.2 任务 #2 ~ #9
> 节奏：单人全职，**11 个工作日**（含 1 天验收缓冲），分 8 个阶段串行为主、部分并行
> 原则：**每阶段末过一道验收门**（映射 §5.4 用例编号），不过门不进下一阶段；成本/合规相关的门（缓存、互斥、敏感过滤）为硬门

## 1. 阶段分解（D1 ~ D11）

### 阶段 1：项目骨架（#2，1 天，D1）
- Taro 脚手架：`config/`（dev/index/prod）+ `src/app.tsx` + `app.config.ts`
- 5 页面占位 + TabBar 三页（发现 / 关注流 / 我的）+ 路由参数约定（§4.1）
- 全局样式：浅色卡片风主题、taro-ui SCSS 变量覆盖、`styles/` 目录
- `src/config/public.ts`（endpoint / publishableKey，§3.8）

**交付**：可在真机预览的空壳 5 页应用。
**验收门 G1**：页面跳转与 TabBar 切换正常；主包体积对比 G0 无异常增长。

### 阶段 2：云 SDK + 登录（#3，1 天，D2）
- `utils/cloud.ts`：`/miniprogram` 子包初始化 + `createDiagnosticWx` 注入（§3.4 代码为准）
- `utils/workbuddy-cloud-diagnostics.ts`：请求失败/超时/鉴权错误的结构化日志
- Auth 微信登录 + `users` collection 首次进入初始化（§3.8）
- `stores/auth.ts`（zustand）

**验收门 G2**：登录后 `users` 有记录；诊断日志可读。

### 阶段 3：搜索 + 消歧 + 敏感过滤（#4，1.5 天，D3 ~ D4 上午）
- `utils/search.ts`：Tavily 适配器（Taro.request，附录 A），无 key 降级返回 null
- `utils/sensitive.ts`：**第一级本地静态敏感名单拦截**（§六.7），命中即拒答态、不进任何网络请求
- `utils/disambiguate.ts`：LLM 消歧候选（领域码 ∈ §1.6 枚举）+「都不是 TA」兜底 + 素材零印证降级
- `personKey` 生成与稳定化；发现页搜索 UI（AtSearchBar + 候选卡）

**验收门 G3**（用例 1、7）：同名消歧产出稳定 `personKey`；名单人物被拦截且 events 无网络侧事件；无 key 搜索走降级路径。

### 阶段 4：报告生成 + 缓存体系（#5，2 天，D4 下午 ~ D6）——**全项目核心，不留并行**
- `utils/report.ts`：非流式 + `json_object`（附录 B）；系统提示词含 §2.3 硬约束 + `refused` 兜底（第二级敏感过滤）
- `sanitizeReport()`：zod 全字段校验 + **URL 白名单强制剔除** + heat/sentiment 校验
- `utils/cache.ts`：
  - `report_cache` 读写 + TTL 24h + **`state=building` 条件写入互斥**（轮询 ≤30s，附录 C 扩展）
  - `feed_cache` + `refresh_quota`（每账号/日 ≤10，原子自增）
- 冷启动引导态（无 key + 缓存空，§2.4）
- `stores/report-cache.ts`

**验收门 G4**（用例 2、3、4、5、6、8、9——**硬门**）：
- 命中不触发生成（events 验证）；白名单剔除生效；双账号并发只生成一次；配额第 11 次被拒；知识模式默认关 + 警示条；三条错误路径有 UI。

### 阶段 5：页面 UI（#6，2 天，D7 ~ D8）
- 报告页：六段卡片化渲染（intro/dynamics/quotes/analysis/timeline/sources）+ 缓存时间双入口 + 免责条 + 橙色警示条 + 骨架屏 + 逐段动画（§3.5 打字机模拟）
- 名人主页：信息卡（热度值/标签/头像占位）+ 动态/名言两 Tab + 「生成报告」
- 关注流：feed_cache 归并 + 下拉刷新（受配额）+ 空态/引导态
- 我的：收藏 / 历史 / 设置（key 管理、知识模式开关、隐私项）

**验收门 G5**：5 页全链路可走通（搜索→消歧→报告→关注→关注流→收藏）；主包体积仍 < 1.5MB，超线即拆分包（报告页 + 主页 → subpackages）。

### 阶段 6：收藏 / 历史（#8，1 天，D9）
- `favorites`（type + hash 防重）/ `history`（保留 50 条裁剪）读写
- 名言「复制这句」（自动附来源）、报告导出/复制全文

**验收门 G6**：收藏防重；历史裁剪；「清空我的数据」可用（§六.5）。

### 阶段 7：埋点 + 合规收口（#9 + #7，1 天，D10）
- `events` 埋点接入 §3.8 事件枚举（9 个事件全覆盖关键路径）
- 隐私清单、免责文案全量核查（报告/分享/周报位）、key 风险提示页（设置页）
- 举报 / 反馈入口（客服会话）

**验收门 G7**（用例 10、11）：走一遍全流程，events 各事件均落库；免责与隐私项齐全。

### 阶段 8：整体验收 + 缓冲（1 天，D11）
- 按 **§5.4 全部 11 条用例**逐条执行并记录结果（通过/失败/整改）
- 体积终检（< 2MB 硬限）、`taro build` 生产构建、真机预览
- 交付物：《验收记录》（11 条用例结果）+ 预览/发布说明（§3.4 发布口径：以 dist/ 为小程序工程）

**验收门 G8 = 发布就绪**：11/11 用例通过；生产构建成功。

| 检查点 | 时间 | 动作 |

## 5. 明确不做（防范围蔓延，对照 §1.4）

AI 问答、两人对比、词云、热度折线、自动推送、分享长图（canvas 仅 P1 验证）、H5 适配、多语言——全部移至 V1.5 / V2。开发期间新增想法一律记入方案文档待办，不进 MVP。

**缺陷修复：真机预览 SyntaxError: Unexpected token {（2026-10-04）**
- 现象：真机预览 `Error: vendors.js(2:102104) SyntaxError: Unexpected token {`。

- 修复 1（工具层兜底）：`project.config.json` → `"es6": true`，即开发工具「详情 → 本地设置 → ES6 转 ES5」。
- 修复 2（产物层根治）：`config/index.js` 增加 `mini.compile.include` 判断函数，把 `zod` / `@tencent-ai` 纳入 babel 编译。
