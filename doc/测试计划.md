## 三、测试策略与分层

### 3.1 基座（零依赖）

| 文件 | 作用 |
| --- | --- |
| `test/harness/cloud-db.js` | 内存版微信云开发 DB。刻意复刻平台行为：单次 `get` 20 条上限、`add` 自动注入 `_openid`、主键冲突抛错、拒绝无条件 `update/remove`；并提供故障注入 `__setFailing(name,on)` 与 `__dump/__seed` |
| `test/harness/env.js` | `@tarojs/taro` 与全局 `wx` 替身、Map 版 storage、`env.load('utils/x')` 加载编译产物、`registerCloudFn()` 注入云函数替身 |
| `test/harness/t.js` | `describe/it/ok/eq/deepEq/rejects` + 汇总 |
| `test/tsconfig.test.json` | 把 `src/utils`、`src/config`、`src/stores` 编译成 CommonJS 到 `test/.build` |
| `test/run.js` | 用例加载与汇总；每个 `fresh()` 清库 + 清 storage + 清模块缓存 + **清云函数替身** |

### 3.2 三层用例

1. **纯逻辑层**（`01-pure.js`，62 例）：时间（含报告新鲜度阈值）、敏感词、领域键、筛选、词云、数据聚合、两人对比、分享文案、主题速览 —— 无 IO、纯函数为主。
2. **数据层**（`02-data.js`，44 例）：`db` 适配层、登录、埋点、收藏（含名言快照字段、报告卡内容摘要、情绪小标记）、历史 —— 跑在真实代码路径 + 内存云 DB 上。
3. **配额与问答**（`03-quota-qa.js`，108 例）：配额云端通道、生成配额、会员权益、问答闸门与计数（含调试开挂与用量展示口径）、问答语料、对比问答、内容安全、提问流程（含联网检索）、会员深度模式、报告质量（素材分级保留 / 点评拆条 / 信源分歧）、报告页会员促销条（免费两态 + 只服务免费用户 + 单行长度预算）、会员中心真实示例（挑行 / 脏行 / 截断 / 只读就绪 / 缓存与失败容忍）。

### 3.3 覆盖口径（重点）

- **降级路径必测**：云函数未部署 → 静默回退本机计数；`ask_quota`/`generate_quota`/`users` 表不可用 → 保守判定。
- **安全方向必测**：机审 fail-open（服务端故障放过）但对命中违规 fail-closed（必须拦下）；镜像计数**只抬不降**（宁可少放行）。
- **计费口径必测**：只有「真拿到回答/报告」才计数；缓存命中、生成失败、机审命中、模型报错都不计数。
- **不可被绕过**：云端计数优先于本机；本机被清数据不会重置账号额度（清掉的只是镜像）。

### 3.4 环境模拟要点

`cloudbaseEnvId` 取自 `src/config/local.ts`（本机已填真实值），故 `isCloudConfigured === true`，云通道与机审在测试中按“已配置”分支执行；未部署分支由“不注册云函数替身”制造（`wx.callFunction` 抛 `-501000`）。

## 六、本轮发现与处理

| 类型 | 问题 | 处理 |
| --- | --- | --- |
| 基座缺陷 | `resetAll()` 未清空已注册的云函数替身，上一用例注入的 `quotaGuard`/`contentCheck` **泄漏**到后续用例，造成 7 例误判 | 在 `resetData()` 中清空云函数注册表 |
| 用例假设 | `or('没有点号')` 的实际行为是**构造期抛错**（不是返回 error） | 改为断言 reject |
| 用例假设 | 默认口径要求素材命中 ≥2 条，实际 `topic` 类豁免 | 用例跳过 `kind === 'topic'` |
| 用例假设 | 对比用例的「无重叠」被关键词真实重叠污染 | 改为构造完全对立语料并断言 `common` 为空 |
| 用例假设 | 同毫秒写入的 `ts` 并列导致「最近一次」顺序不稳 | 用例显式拉开时间，并单列「同毫秒只保证去重」用例 |
| 用例假设 | 历史裁剪用例的种子数据未绑定当前用户 | `seedHistory` 增 `userId` 参数并断言新记录保留 |
| 用例假设 | 会员到期天数用「+2 天」断言 3 天，实际因毫秒差取整为 2 | 改用 +1.5 天断言 2 |
| 用例假设 | `env.storage` 是原始 Map，删除后为 `undefined` 而非 `''` | 改用 `has()` 断言已移除 |
| 用例假设（口径漂移） | 建议问题用例仍按**旧上限 3 条**断言，实际 O-12 已放宽到 8 条（面板分批轮转「换一批」） | 改为断言上限 8 条，并补前三条顺序不变（观感与改版前一致）的断言 |
| 用例假设（口径漂移） | 会员权益用例仍按**旧条目数 3** 断言，实际已是 5 条（+ 时长顺延、热门榜可见位数） | 改为 5 条；并新增「热门榜分档」用例（免费 6 / 会员 24 与常量、文案同源） |
| 覆盖缺口 | `utils/share`（O-13 新增，纯函数）与 `utils/time` 新增的报告新鲜度阈值无用例 | 补「分享文案与落地路径」套件（6 例）与报告新鲜度 2 例（阈值 14 天一处定义、未知生成时间不算陈旧） |
| 覆盖缺口 | `utils/member` 新增的报告页价值条判定（O-21）与 `utils/member-sample`（O-22）无用例 | 补「报告页会员促销条」套件（O-21 时 3 例；**O-25 收敛后为 4 例**：`presentSections` 顺序与空值口径、免费「有专享段」点名实际存在的那几段、免费「无专享段」不承诺当前这一份 + 单行长度预算、促销条**只服务免费用户**（`reportMemberPromo.length === 1` 且旧四态函数已删除））与「会员中心真实示例」套件（8 例：跳脏行 / 只取第一条分歧 / 只节选不摘要 / 只读 `state=ready` / TTL 复用 / 读库失败返回 null） |
