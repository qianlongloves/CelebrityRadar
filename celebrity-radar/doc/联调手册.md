> ② **用量文案太长**（`components/qa-panel/index.tsx`）—— 右侧「免费版 · 今日还可问 N 次」（14 字）与名字在同一行，名字越长它越显突兀，反过来又把名字压到省略。压缩为「免费版 · 剩 N 次」（9 字），开挂态同步缩短；`__left` 补 `white-space: nowrap`（不折行、不收缩）。删「今日」不是丢口径 —— 每日额度这件事由升级条（「每日提问提到 N 次」）负责说清，而这行占的是与名字同一行的宽度。
> ③ **影响面**：`components/qa-panel` 为三处共用，改动随之生效于 `pages/qa`（本项主诉）、`pages/ask`（底栏页，第三十五次校正刚瘦过身）、对比页对比问答。
> ④ **没做的**：名字没有留两行（完整显示 + 「报告 ›」跟在其后）—— 那要把两个 `Text` 改成内联混排，且卡头会随名字长短变高，比省略号更不可控；名字是回报告页的入口，报告页顶部有完整名字，省略不影响可达性。
> ⑤ **上线动作：无**（无新增集合 / 云函数 / 页面 / 组件 / 依赖 / 人工配置，**不消耗生成额度**，**无新增读请求**）。用例总数**仍为 24 条**（纯样式与文案，无用例变动）；`npm test` 通过 **216 / 216**，主包 **1214KB → 1215KB**（+1KB）。

**三条必背口径**：
1. 主键是系统的 `_id`（端上写 `id`，由 `utils/db.ts` 映射）；`users` 由云端生成，`refresh_quota` / `generate_quota` / `ask_quota` / `orders` 由云函数写入，其余均由端上指定 ⇒ 天然防重，**无需唯一索引**。
2. `report_cache` / `feed_cache` **不能**设成「仅创建者可读写」：抢锁要跨用户 update 他人的过期 `building` 行，否则「刷新最新」与并发抢占失效（见《云开发配置手册.md》§四）。
3. `generate_quota` / `refresh_quota` / `ask_quota` / `orders` 四张表**端上只读、不可写**：写入只允许云函数（`quotaGuard` / `payCreate` / `payCallback`）。⚠ 前三张配额表的权限**必须在 `quotaGuard` 部署成功后再收紧**，顺序颠倒会让计数恒为 0、免费额度失效；`ask_quota` 还多一条：部署的必须是**含 `ask` 类的新版本** —— 旧版本部署着也白搭（自增报「未知 kind」），端上表现为云端恒 0、额度判定回退本机镜像（不会真漏额度，但读数不一致）。
4. `hot_board` 的 `read` 必须是 `true` —— 首页是 tabBar 页，**未登录也要能看榜**（榜单不含个人信息）；而 `write` 可以直接收到 `false`，因为写方**只有 `hotBoardRefresh` 一个云函数**，云函数是管理员身份、不受安全规则约束（与 `report_cache` 那种「端上要抢锁」的共享缓存不同，**顺序无依赖**，端上从不写它）。

**收藏卡内容用例补充说明**（O-23 · 2026-10-08）：
- 报告卡的「最新 / 素材」两行是**回源 `report_cache`** 取的（收藏存的是快照，payload 只有 heat / mode / generatedAt），与走势条**共用同一次批量读**（一次 `in` 查询、≤12 张卡）—— 收藏页比改版前多一次云读属预期，**不额外增加读请求、不消耗生成额度**。
- 这两行**只认版本一致**的快照；点「刷新最新」后内容消失是**刻意**的（不是加载失败），理由见上。
- 「最新」优先取 `coverage.latest`（博查原值），取不到才退回**日期最新**的动态；**没有日期的条目不参与比较** —— 若卡片上冒出没日期的旧条目，属 bug。
- 新增内容一律**取不到就不渲染**：收藏页里不应出现「暂无 / 空 / —」这类占位文案。
- 名言卡的 `background` / `note` 是**本轮起才落库**的：2026-10-08 之前收藏的名言**必然**少这两段。**解法是重新收藏同一条**（`writeFavorite` 走 update 刷新内容快照、`created_at` 保持不变），**不需要手工改库**；重新收藏后「收藏于 N 天前」的日期**应当不变**，若变了说明写成了新增而非更新。

- 带日期条目少于 3 条时**整卡不渲染**（与词云 < 4 词同一取舍），此时报告页少一张卡属预期。

**消息中心用例补充说明**：
- 未读口径是**本机的**，且**逐条记**：已读记录存 `messages:read_ids`（条目 id 列表，上限 300 条，超出裁掉最旧的），不落云、不做多设备同步，故「换台设备红点重新亮」属预期（刻意取舍 —— 不为一条已读记录新增集合与权限配置）。
- **进页面不再自动全标已读**（旧版行为已改）：未读要用户点开某条、或点顶部「全部已读」才会清掉，所以「退出再进来，没看过的仍是未读」是**预期**而不是 bug。旧版留下的 `messages:read_at` 基线仍在参与判定（只读不写），老用户升级后不会凭空多出一堆未读。
- 关注更新复用关注流页的 watch（**同一份 60s 内存缓存**），判定 = 关注之后 `report_cache` / `feed_cache` 有更新的时间戳；点长内容的卡片只是展开，**跳转要单独点「查看详情 ›」** —— 展开的是内容，离开页面得让用户明确点。
- 折叠阈值 = 正文超过 **42 字**（约两行）：超过才折叠、才显示「展开全文」。三条公告的正文都在 55 字以上，所以公告一律折叠属预期；关注更新与周报条目的副标题短，通常不折叠、点一下直接进详情。
- 平台公告是静态清单（`config/notices.ts`）：**改动历史公告的 `date` 会让它重新变成未读**；新增公告加在数组头部即可，发布不需要任何后台操作。
- 关注更新最多覆盖前 30 位关注（每位要读两次缓存，不做无上限拉取），超过时页面底部有小字提示 —— 属预期，不是漏做。

**周报用例补充说明**：
- 逐人卡片里的**人名与其动态条目直接取自 `feed_cache`**，不是模型输出 —— 若发现周报「少了某位关注人」，说明该人缓存里没有**最近 7 天**的条目（属预期），而不是模型漏写；点条目右侧「复制链接」可核对原文。
- 模型只负责综述 / 逐人摘要 / 话题词。令模型拒答（或返回空文字）时应降级为「素材清单」，页顶出现「本次未生成 AI 概述」提示条，**不应**白屏或报错。
- 缓存键为 `weekKey`（`yyyy-Www`，本机 storage，前缀 `weekly:`），故「我的 → 系统设置 → 清空数据」后周报缓存也应一并消失（重新进页需再生成）。

**对比用例补充说明**：
- 对比是**零模型调用的端上聚合**（`utils/compare.ts`）：结果完全由两份**已缓存**报告算出，换人重选、反复进出都不触发任何生成请求，**也不消耗额度** —— 这正是不做成「输入两个名字现生成」的原因（见《设计方案》§2.1 M4）。
- 「对比」**不做优劣断言**：只有热度与报道量标出更高的一方（那是同一把尺子的曝光度读数），动态 / 言论 / 履历条数**只并列、不给箭头** —— 这是产品口径，不是渲染缺失，验收时不要当缺陷提。
- 候选名单取本机**关注列表 + 浏览历史**去重后的前 20 位（不额外请求、不需要再搜一次）；若「少了某个想看的人」，属预期（没关注过、也没浏览过），可先搜一次该名人再来对比。
- 两位名人的热点话题通常并不重合，故「公开立场」是**并排呈现而非强行配对**；「共同关注点」来自双方素材的用词重叠，为空时是正常结论（说明他们最近被讨论的事几乎不沾边），不是 bug。

**分享卡片用例补充说明**：
- 卡片**不上传云存储**：保存相册与图片转发都只吃本地临时路径，因此 CloudBase **Storage 里不应出现任何用户卡片文件** —— 这是刻意取舍（不给云存储留用户私人收藏的副本），不是漏做。
- 图上头像为「领域色圆 + 姓名首字」占位，**不是真实头像**（全项目一致）；卡片因此零网络图片依赖，**断网也能出图**，也不会占 request 合法域名。
- 卡片高度**固定**（名言卡 3:4 取 520），名言过长时按行截断补「…」属预期 —— 完整内容仍在报告页 / 收藏页。
- 出图失败（基础库 < 2.9.0 等）时弹层内显示「卡片生成失败」+ 原因，两个动作按钮置灰 —— **不应**出现无反应的按钮。

**时间线 / 立场与舆情 / 模型选择用例补充说明**：
- 时间线 Tab 与「立场与舆情」卡都**只读报告缓存、不触发任何生成、不消耗额度**；进主页 / 报告页即渲染，没有「正在生成」态。
- 「立场与舆情」是**统计口径**而非对人物的评价：① 情绪走向条的条数直接来自模型对每条动态的 `sentiment` 标注（三值枚举在 `utils/report.ts` 强校验），衡量的是「媒体近期报道的语气分布」，不是「这个人的好坏」；② **话题态度**（`stance` 段，四值倾向 `positive|neutral|negative|mixed`）由模型依同一批素材判定，**每条都附一句话依据**，属可核对项 —— 自由文本无 URL 那样可白名单的锚点，故只做「去空 + 限 4 条 + 依据截断 60 字」。老缓存（2026-10-06 前生成）没有 `stance` 字段，那张卡只显示情绪走向条与统计说明，**属预期，不是缺字段**。
- 模型偏好存**本机**（storage 键 `settings:llm_model`），换设备后回到默认模型；「我的 → 系统设置 → 清空数据」会一并清除该偏好。
- 若把 `llm.models` 里的某项删掉，端上会**自动回落到 `llm.model` 默认值**（见 `utils/llm.ts#resolveChatModel`），不会带着一个已下线的模型继续请求，老设备无需手动改回。

**收藏页用例补充说明**（v1.4 补记 · 八）：
- 卡片左侧是**名人头像**（领域色圆 + 姓名首字），**不是真实头像**（全项目一致）：平台不抓取也不缓存名人照片，见《设计方案》§六 4。取不到姓名首字时显示**「?」**，属预期降级而不是样式坏了。
- **备注功能已整体删除**：列表、详情与用例里都**不应**再出现「加备注 / 编辑备注 / 保存备注」任何入口；`favorites` 里的老 `note` 字段**不再读取**（历史数据不清理，也不该在界面上冒出来）。
- **星标是「已收藏」状态 + 点按取消**（与报告页语录的 ★/☆ 同一套符号），点按后弹二次确认；确认后该条**立即从列表消失**且**不可撤销**（要恢复只能回报告页重新收藏）。核对 `favorites` 里该行确已删除。
- **下拉刷新不消耗任何额度**（只重拉列表）：验证方式是在报告页取消一条收藏 → 返回收藏页下拉 → 该条消失，同时「我的」页今日生成次数**不变**。两个入口页（tabBar「收藏」与二级页「我的收藏」）都要各试一次。
- 筛选 chips（全部 / 报告 / 名言 / 动态 / 履历）带计数；切到某类为空时给「查看全部」空态，**不应**白屏。报告卡正文是**热度刻度**（0~100，与热门榜同口径），动态卡正文为标题 + **最多两行**摘要。

**内容安全机审用例补充说明**（✅ 重新可执行 · 2026-10-07）：
- ✅ **送检源已恢复**：随 AI 问答（M4-8）落地，送检文本 = **用户在 `pages/qa` 的提问**（`utils/qa.ts#askReport` 在组 prompt **之前**调 `checkUserText`，命中违规即拦、**不发起模型请求**）。此前「无接入点」状态（2026-10-06 收藏备注删除导致）已结束：云函数 `contentCheck` 由「暂缓」转为**待部署**，不部署仍不影响功能（端上 fail-open 放行，只少一道合规兜底）。核对用例 16③ 时注意：拦截发生在请求之前，故模型调用数不应增加。
- AI 生成的报告 / 名言、以及只画既有内容的分享卡片**不送检** —— 它们不出本人可见范围、也不构成内容出口，逐条送检只增时延与调用量（见《名人雷达_设计方案.md》§六 3）。
- 服务端是**云调用**（`cloud.openapi.security.msgSecCheck`），凭证由平台托管：函数里**没有也不需要** `access_token` 环境变量。若调用报权限错误，先查 `cloudfunctions/contentCheck/config.json` 的 `permissions.openapi` 是否**随上传生效**（微信云函数控制台 → 该函数 → 配置 → 权限可以看到）。
- **fail-open 是刻意取舍**，不是缺陷：送检文本仅本人可见，漏拦的实际风险远小于「服务端没配好就让用户输不了字」。判据：未部署 / 上游抖动时用例 16① 必须**放行**；只有 ③ 那条真违规才该被拦下。
- 空输入与「内容未变」两条路径**不打上游**（前者省一次调用、后者连函数都不进），所以 ④⑤ 看不到「校验中…」，属预期。

**关键词云用例补充说明**：
- 词云是**统计结果，不是模型输出**：它只聚合已落库报告里的动态标题 / 摘要与语录原文，所以**不会出现报告里没有的说法**；「高频观点」逐条给出原文标题与媒体名供核对。这也是刻意不做「AI 总结观点」的原因 —— 那会引入无法核对的二手表述。
- 两类词的来源不同：**带描边的是模型判定的话题**（`stance[].topic`，质量最高，不受「≥2 条命中」约束、也豁免重叠收敛）；其余是按词频统计出来的说法，字号只代表「提及它的素材条数」。
- **词条 < 4 个时整卡不渲染**属预期：素材本来就少的报告，词云只会是一堆零散碎片，宁可不摆。
- 中文没有词边界、端上也装不下词典，所以口径是「n-gram + 强过滤」而非真分词，偶发生涩搭配属正常；但**跨词碎片（如「发布新一」「旗舰手」）已被过滤掉**，真机上若看到明显碎片属需要修的过滤规则，请记录原词。
- 看词云**不消耗生成额度**，也不触发抓取（只读本机报告缓存）。

**数据 Tab 用例补充说明**：
- 数据 Tab 是**零模型调用的端上聚合**（`utils/stats.ts`）：只读报告里已落库的 `dynamics` / `timeline` / `coverage`，老缓存不重新生成也有；进主页即渲染，**没有「正在生成」态**。
- 四张卡**全部可核对**：热度与报道量取自本份报告的 `heat` / `coverage`，来源分布与情绪构成取自同一条 `dynamics`，时间分布取自「动态 + 时间线」的日期 —— 同一份数据、同一套情绪配色，与报告页任意一处的读数都**不该互相矛盾**。
- **算不出来就说算不出来**：老报告没有 `coverage` 字段时报道量显示「—」而不是 0；样本不够的卡整块不渲染 —— 给一张由一两条数据凑出来的「分布」比不给更糟（与词云 < 4 词、折线 < 3 点同一取舍）。
- 来源分布做了**同媒体归并**（互为子串的名称算一家，如「新浪」与「新浪娱乐」），所以条形条数可能**少于**「近期动态」里的媒体写法种数 —— 属预期，不是丢数据；脚注里的「N 条无来源标注」是模型没给 `source` 且 url 无主机名的那些条目。
- 时间分布的横轴只标月份数字、区间写在脚注；窗口是按月连续的一段（最多 12 格），**跨年时照旧连着画**（如 2026-03 ~ 2027-02），不按年份切成两张。
- 数据 Tab **不新增集合、不新增云函数、不改 Schema、不引图表库**（条形与柱状都是 View + 宽度 / 高度百分比），故主包只 +13KB。

**指标出数口径**（上线首日）：缓存命中率 = `report_hit_cache / (report_hit_cache + report_generate)`；周报生成量单看 `weekly_generate`（**勿并入** `report_generate`，否则成本口径被污染）；人均关注数从 `follows` / 活跃用户；留存从 `events` 首末次出现日期。

**分享覆盖用例补充说明**（O-13 · 2026-10-07）：
- 全项目分享文案**只有一个出口** `utils/share.ts`（`personShareTitle` / `reportSharePath`），四处（报告页 / 名人主页 / 发现页 / 底栏「AI 提问」页）都是调它 —— 若看到某页标题格式不一致（多出「· 深度报告」这类后缀、或丢了「姓名 · 领域」），那是漏接该出口，属 bug 而不是文案差异。
- **落地页必须是 `pages/report/index`**：tabBar 页**不能作分享落地页**，所以「发现页」「AI 提问」这类 tabBar 页分享时一律落到**具体某个人的报告页**（发现页落「横幅上的今日名人」、提问页落「当前选中的人」、未选出人时退回今日名人）。核对分享链接时看 path 上有无 `personKey`，**没有 `personKey` 的报告页链接是无对象链接**，属配置漏做。
- 报告页分享**不再带「深度报告」后缀**，与他人主页 / 发现页 / 提问页同源；`pages/qa`（报告页入口的会话页）**不单独注册分享** —— 它与报告页同人同语料，分享它等于分享报告页。
- 分享出的文案都**能在报告里指回去**（标题里的那句话就是页面上本来在展示的 `intro` 首句），**不带未核实结论**；`pages/collection` / `pages/mine` / `pages/feed` / `pages/messages` / `pages/history` / `pages/member` **仍未注册分享**（这些页没有「可分享的具体对象」，分享出去只能是通用邀请），属**记录在案的取舍**、不要当缺陷提。

**报告新鲜度用例补充说明**（O-14 · 2026-10-07）：
- 阈值**只有一处**：`utils/time.ts` 的 `STALE_REPORT_DAYS = 14`（`reportAgeDays()` / `isStaleReport()`）。问答会话头部、报告页「查看最新」前、收藏卡、历史页「继续看」四处**同阈值**；若某处显示的阈值不同，属漏接该函数。
- 出现条件要分清：报告页 / 收藏卡的 `建议刷新` 标记**只在 ≥14 天时出现**，不足 14 天时该标记**不该出现**，但「生成于 N 天前」这类中性时间文案一直都在。
- **收藏卡标的是快照年龄，不是缓存版本**：收藏存的是收藏那一刻的 `payload`，报告页点「刷新最新」**不会**更新这条收藏卡上的时间与标记 —— 属预期。
- 标记是**纯本机计算**：不新增云读（历史页那次批量读除外，见下）、不发任何生成请求、**不消耗额度**。

**继续看用例补充说明**（O-15 · 2026-10-07）：
- 「继续看」只在**历史页**（「我的 → 查询历史」二级页，与 tabBar「收藏」页共用 `components/records-view` 之外的 `history-view`）出现，最多 **3 张卡**（`CONTINUE_MAX = 3`），顺序 = `listHistory()` 的时间倒序（最近看过的在最前），**不另排序**。
- 卡上显示的报告年龄来自**一次 `getCachedReports` 批量读**（`in` 一次往返、≤3 份）—— 因为 `history` 表只存「谁、什么时候看过」，**不存报告版本**；读不到缓存时卡上显示「未生成报告」，**不触发生成**。
- 历史页的**完整列表**仍只用本机已有的浏览时间（`fromNow`），**不做额外读** —— 所以「继续看」比下方列表多一轮轻量云读属预期，不要当重复请求。
- 「继续看」只读缓存，**不消耗生成额度**；收藏页**没有**这一行（收藏页的回流标记见 O-14 的「建议刷新」胶囊）。

## 五、搜索素材来源：现状（旧「三选项」已作废）

**旧结论为何作废**：早前依据 `@tencent-ai/workbuddy-cloud-sdk@0.1.3` 只有 `auth/database/storage/llm` 四模块、**无云函数通道**，推出「必须自建后端才能代持 key」的三选项（A 自建服务 / B key 存表 / C 本机 key）。
**迁到 CloudBase 后该前提不成立**：微信云开发**天生提供云函数**，平台自有 key 只存函数环境变量即可，端上零配置 —— 这正是原 A 方案的等价物，且**已落地为 `aiProxy`**。

**现行为唯一通道：平台代付（端上 `utils/llm.ts` / `utils/search.ts` 同构实现）**：

| 通道 | 场景 | key 存放 | 落地位置 |
|---|---|---|---|
| **平台代付** | 用户零配置即可生成 | 云函数环境变量 `BOCHA_API_KEY` / `DEEPSEEK_API_KEY` | `cloudfunctions/aiProxy`（`test` / `search` / `chat`） |

**取用顺序**：没有第二条路可回落，通道不通即报告落 `coldstart` 引导态（服务端没配好时端上不再静默降级）。

**为何砍掉「本机直连」（原 ② BYOK）**：直连要求每个使用者自备 DeepSeek / 博查 key，等于把门槛转嫁给用户，产品无法对外发布；且本机 key 含中文时 `wx` 的 `setRequestHeader` 会抛 `String contains non ISO-8859-1 code point`（真实踩过）。收敛后 `utils/settings.ts` 只剩「清理历史遗留密钥」一个职责（挂在「清空我的数据」上），旧键位 `settings:bocha_api_key` / `settings:llm_api_key` 已不再被任何代码读写。

> ⚠ **检索源校正**：早前文档通篇写 Tavily（`api.tavily.com` / `getTavilyKey()`），但 `utils/search.ts` **早已迁移到博查**（`https://api.bochaai.com/v1/web-search`、storage key `settings:bocha_api_key`）—— 博查是**国内备案域名**，可直接配进小程序 request 合法域名。旧 Tavily 残留键仅由 `utils/settings.ts` 在「清空我的数据」时清理，不再读写。
