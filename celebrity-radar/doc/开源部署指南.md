# 开源部署指南（从零到能跑）

> README §五「快速开始」只讲**怎么编译**；本文讲**编译之后还要补什么**，
> 以及每一步「不做会怎样」。
>
> 目标形态：自己的小程序 → 自己的云开发环境 → 跑通「搜人名 → 生成报告」。
> 会员支付、订阅推送、定时任务都是**可选**，可以先把主链路跑通再回来配。

---

## 零、先认清：开源的是代码，不是服务

| 你需要自备 | 用途 | 不配的后果 |
|---|---|---|
| 小程序 appid + 主体资质 | 微信要求 | 无法真机预览，无法上线 |
| 云开发环境（腾讯云 CloudBase） | 数据库与 7 个云函数都跑在这里 | 登录与**全部** DB 调用不会发起，「我的」页显示红字「云服务未配置」 |
| DeepSeek API Key | 生成报告（经云函数 `aiProxy` 代打） | 生成报错；已有缓存的浏览、收藏仍可用 |
| 博查（Bocha）API Key | 联网检索素材 | 检索为空，报告缺素材、时间线不完整 |
| ICP 备案 / 服务类目 | 上线审核 | 只影响发布，不影响本地调试 |

> 本仓库**不含任何可用凭据**。上游 key 只以 `${env.XXX}` 占位符出现在 `cloudbaserc.json`，
> 真实值在部署时从 `.env` 读取。详见第六节「密钥从哪来、去哪了」。

## 一、拉代码 + 三份本地配置

```bash
git clone <仓库地址>
cd celebrity-radar/celebrity-radar

cp src/config/local.example.ts            src/config/local.ts                       # ① 端上本地配置
cp project.private.config.example.json    project.private.config.json               # ② 开发者工具私有配置
cp .env.example                          .env                                      # ③ 云函数部署密钥

npm install
```

三份文件都**不进版本库**（已在 `.gitignore` 里），所以改动不会污染工作区、也不会随 PR 提交。
其中 ① 是**必做**的 —— `src/config/public.ts` 直接 import 它，没复制会编译报 `Cannot find module './local'`。

## 二、开通云开发，填环境 ID

1. 微信开发者工具导入 `celebrity-radar/` 目录（`miniprogramRoot: dist/`，`cloudfunctionRoot: cloudfunctions/`）；
   此时会要求填 appid —— 填你自己的（或直接改 `project.config.json`）。
2. 工具栏「云开发」→ 开通环境，记下**环境 ID**（形如 `celebrity-radar-1a2b3c4d`）。
3. 把环境 ID 填到两个地方：

| 位置 | 字段 | 谁读它 |
|---|---|---|
| `src/config/local.ts` | `cloudbaseEnvId` | 小程序端 `wx.cloud.init` |
| `.env` | `TCB_ENV_ID` | `cloudbaserc.json` 的 `envId`，即 CloudBase CLI 部署时 |

若你的 CloudBase CLI 版本不解析该变量，直接把 `cloudbaserc.json` 顶部的 `envId` 写成环境 ID 字面值即可。

> **这一节的判定信号**：填完后「我的」页不再显示红字「云服务未配置」，登录会自动发起。
> 代码里的判据是 `utils/cloud.ts#isCloudConfigured`（`cloudbaseEnvId` 仍含占位串 `REPLACE_ME` 时为 false）。

## 三、部署云函数

`.env` 里至少填这两个，否则生成链路不通：

```
DEEPSEEK_API_KEY=...
BOCHA_API_KEY=...
```

```bash
npm i -g @cloudbase/cli     # 只需一次
tcb login                   # 只需一次
cd celebrity-radar/celebrity-radar
tcb fn deploy aiProxy       -e <your-env-id>
```

**两种部署方式的差别值得记住**（这是本项目最容易踩的坑）：

| 方式 | 环境变量 / 超时 / 触发器 |
|---|---|
| CloudBase CLI（`tcb fn deploy`） | 读仓库根 `cloudbaserc.json`，**一并下发**，不用手工补 |
| 微信开发者工具右键「上传并部署」 | **只上传代码**，不读 `cloudbaserc.json` ⇒ 环境变量、超时、触发器都得到控制台手工补 |

⚠ 三个函数（`aiProxy` / `hotBoardRefresh` / `notifyFollowUpdates`）的执行超时必须是 **60 秒**，
平台默认 20 秒会把长报告、一轮「6 检索 + 1 生成」直接掐断（端上报 `-504003`）。

按需部署（不用的功能不部署也不影响其他部分）：

| 函数 | 何时需要 |
|---|---|
| `aiProxy` | **核心**，生成报告 / 检索 / AI 问答都走它 |
| `quotaGuard` | 配额服务端化，建议部署（须在收紧配额表权限**之前**部署） |
| `contentCheck` | 内容机审（fail-open，不部署只是少一道合规兜底） |
| `hotBoardRefresh` | 首页热门榜每日更新（需定时触发器 06:30） |
| `notifyFollowUpdates` | 关注更新订阅推送（需模板 + 定时触发器 09:00） |
| `keywordAlert` | 关键词舆情预警（需模板 + 定时触发器 09:20） |
| `payCreate` / `payCallback` | 会员支付（需自己的商户号） |
| `dbInit` | **运维工具，不是运行时依赖**，建表/建索引时才部署，用完可 `tcb fn delete dbInit` |

## 四、建集合与权限

**22 张**集合用运维函数 `dbInit` 最省事（逐张清单见《云开发配置手册.md》§二）：

```bash
tcb fn deploy dbInit -e <your-env-id>
tcb fn invoke dbInit -e <your-env-id> --params '{"action":"report"}'   # 只读巡检，先看缺什么
tcb fn invoke dbInit -e <your-env-id> --params '{"action":"init"}'     # 建集合
```

⚠ **写操作需要口令**：先给 `dbInit` 配环境变量 `DB_ADMIN_TOKEN`（**32 字节随机串**，如
`openssl rand -hex 32`；别用 `admin888` 这类可猜串），调用时带 `"token":"<同一个串>"`。
未配置该变量时写操作**一律拒绝**（只读巡检不受限）—— 这是防止「云函数被端上任意调用」的闸门，别省。
改口令后要 `tcb fn deploy dbInit` 重部署（`tcb fn code update` 不带环境变量）。

**权限没有接口能改，只能在控制台手工设置**，12 张表逐表取值见
[`doc/云开发配置手册.md`](./云开发配置手册.md) §四。最容易出事的两条：

- 三张配额表（`generate_quota` / `refresh_quota` / `ask_quota`）必须设成「本人可读、**不可写**」，
  否则用户能自己改额度 ⇒ 免费层失效。⚠ 必须先部署 `quotaGuard` 再收紧，顺序颠倒会让计数恒为 0。
- `report_cache` / `feed_cache` 是「所有人可读、登录可写」的共享缓存。

索引可以程序化建（`dbInit` 的 `action:"indexes"`），也可以按 §五 手工建。

## 五、编译与预览

```bash
npm run build:weapp     # 产物 dist/，微信开发者工具直接刷新即可
npm run build:h5        # 浏览器里调试用（云开发相关功能不可用）
npm test                # 纯本地单测，不需要云环境
```

真机预览前记得在「公众平台 → 开发管理」配：

- **request 合法域名**：`https://api.bochaai.com`、`https://api.deepseek.com`
  （云数据库 / 云函数走 `wx.cloud`，**不占**域名）
- **用户隐私保护指引（平台侧）**：在「设置 → 基本信息 → 用户隐私保护指引」按**实际**收集情况勾选 ——
  真实收集项不止「匿名标识 openid、本地存储」：还有云数据库里的**关注 / 收藏 / 浏览历史 /
  关键词与名人监控 / 舆情跟进状态 / 会员订单**与**行为计数统计**（面向用户的权威口径见
  `src/pages/agreement/index.tsx` 的隐私清单）。⚠ `src/app.config.ts` 已声明
  `__usePrivacyCheck__: true`，**指引未配置并过审前不要发版**，否则头像 / 昵称等隐私接口会被平台直接拒绝。
- 客服功能（「内容举报 / 反馈」依赖 `open-type="contact"`）

## 六、密钥从哪来、去哪了

| 密钥 | 存放位置 | 会不会进小程序包 |
|---|---|---|
| `DEEPSEEK_API_KEY` / `BOCHA_API_KEY` | 云函数环境变量（部署时从 `.env` 读） | ❌ 不进 |
| `WX_APPSECRET` | 云函数环境变量：`dbInit`（建索引用）+ **三个定时推送函数**（`notifyFollowUpdates` / `keywordAlert` / `riskWatch`，定时器拿不到云调用的自动鉴权，只能自取 `stable_token` 发订阅消息） | ❌ 不进 |
| `DB_ADMIN_TOKEN` | `dbInit` 环境变量（自定义口令） | ❌ 不进 |
| `WX_PAY_SUB_MCH_ID` | `payCreate` 环境变量 | ❌ 不进 |
| 环境 ID / 订阅模板 ID | `src/config/local.ts` | ✅ 进（**它们不是密钥**） |

端上**零密钥**：所有上游请求都由云函数代发，客户端不持有任何 key，用户也不用填任何东西。
`src/config/local.ts` 会打进包，所以只该放「不是密钥、但跟机器走」的值。

## 七、常见卡点

| 现象 | 原因 | 处理 |
|---|---|---|
| 编译报 `Cannot find module './local'` | 没做第一节的 ① | `cp src/config/local.example.ts src/config/local.ts` |
| 「我的」页红字「云服务未配置」 | `local.ts` 的 `cloudbaseEnvId` 还是 `REPLACE_ME` | 填自己的环境 ID |
| 生成报错、端上 `-504003` | 云函数超时仍是默认 20 秒（用开发者工具上传的） | 控制台把超时改成 60 秒 |
| 检索有结果但报告内容空 | 模型返回超时或 JSON 校验不过 | 看 `aiProxy` 日志；默认模型名必须是上游真实存在的 |
| 免费额度怎么点都不减 | 配额表权限没收紧，或 `quotaGuard` 部署顺序颠倒 | 见第四节 |
| 订阅推送收不到（43101） | 两个定时任务共用了一枚模板 | `subscribeTemplateId` 与 `alertTemplateId` 必须不同模板 |
| 会员开通点击无反应 | 未配商户号 / 未部署 `payCallback` | 见第三节可选函数，不影响免费功能 |
