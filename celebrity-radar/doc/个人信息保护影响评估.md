## 一、触发情形判定（PIPL 第 55 条逐项）

| 第 55 条情形 | 是否触发 | 判定理由 |
|---|---|---|
| (一) 处理**敏感**个人信息 | **是（从严口径）** | ① 支付订单含微信支付单号与金额，属与**金融账户**相关的交易信息，从严按敏感信息对待；② 不满 14 周岁未成年人的个人信息属敏感信息 —— 本服务面向成年人，但**不排除**未成年人使用，故按「可能发生」评估（见 §五.2） |
| (二) 利用个人信息进行**自动化决策** | **否** | 报告 / 舆情分级 / 热门榜都是**基于公开检索内容**生成，**不使用用户个人信息**做输入；榜单全站同一份（`hot_board` 固定 `_id=latest`）、报告按 personKey 全局共享（`report_cache`），**无个性化推荐、无差别定价**。「关注流」是按用户自己订阅的名单聚合，属「提供其已请求的内容」，非自动化决策 |
| (三) **委托处理 / 向他人提供 / 公开**个人信息 | **是** | 检索与内容生成委托第三方服务商处理（见 §四.1）。发送内容为公开检索词与公开网页内容，**不含账号标识、昵称、头像**；本服务**不向公众公开任何用户个人信息** |
| (四) 向**境外**提供个人信息 | **潜在是（当前否）** | 备用检索源（Serper / Tavily，服务器在境外）**默认关闭**：`SERPER_API_KEY` / `TAVILY_API_KEY` 留空即不装配（`cloudfunctions/aiProxy/index.js#BACKUP_PROVIDERS`）。一旦填 key 即构成出境，须先完成 §六 前置条件 |
| (五) 其他对个人权益有重大影响 | **否** | 无征信、无生物识别、无行踪轨迹、无定向推送、无公开用户信息的行为；唯一「公开解读」的对象是**公众人物的公开信息**（见 §五.4） |

> 「触发」不等于「不能做」，而是「必须评估并记录」。本文件即该记录。

## 二、第 56 条(一)：处理目的与方式是否合法、正当、必要

### 2.1 合法性基础

| 处理活动 | 合法性基础 | 落实位置 |
|---|---|---|
| 登录与账号（openid、昵称 / 头像） | **同意**（首次进入的知情同意弹窗；政策版本变化后重新征求） | `src/components/consent-gate`、`src/utils/consent.ts`、`src/app.tsx` |
| 关注 / 收藏 / 历史 / 监控 / 舆情跟进 | 同意 + **履行服务所必需**（用户主动创建） | `src/utils/{follows,favorites,history,keyword-alert,risk-watch,opinion-store}.ts` |
| 会员订单与退款 | 同意 + **法定义务**（《电子商务法》交易记录留存） | `cloudfunctions/{payCreate,payCallback}` |
| 行为埋点（计数） | 同意（政策「使用统计」条已披露用途：成本与稳定性分析，**不用于画像与营销**） | `src/utils/events.ts` |
| 涉政涉军检索的拒绝处理 | **拒绝权 / 合规红线**，不属「收集」 | `src/utils/sensitive.ts`、`cloudfunctions/contentCheck` |

**前置门槛**：平台级隐私校验已开启（`src/app.config.ts#__usePrivacyCheck__: true`），
微信侧「用户隐私保护指引」须与政策一致 —— 两者不一致时平台会拒绝相关接口调用。

### 2.2 正当性与必要性（最小必要）

- **不收集**：手机号、位置、通讯录、麦克风、相册（除用户主动保存分享图）、身份证件、生物识别。
- **账号标识不出域**：openid 只在境内云函数内用于判会员与限额，**不随请求发往任何上游厂商**。
- **本机数据不上传**：缓存索引、限流冷却时间等仅存本机 storage，不参与同步。
- **用户自由文本只有一处**：AI 提问的问题原文（`src/utils/qa.ts`），**不写入用户数据库**，
  仅随该次请求转发用于生成回答；且**机审在前、联网在后**（命中违规的提问不会被第三方检索一遍）。
- **来源缺失不编造**：舆情要点 / 时间线在缺来源时显式写「来源未标注」，保证可追溯
  （`src/utils/weekly-brief.ts`、`src/utils/opinion-rank.ts` 的合规红线注释）。

## 三、处理活动清单（按目的分组）

**含个人信息**的载体（带 openid 或可关联到特定用户）：

| 目的 | 数据类别 | 载体 | 权限收口（`schema.js` ACL） | 保存期限 |
|---|---|---|---|---|
| 账号 | openid、昵称、头像 fileID、设置、活跃时间 | `users` | 仅创建者可读写 | 至删除 / 注销 |
| 会员权益 | openid、套餐、到期时间 | `memberships` | **客户端不可读写**（仅云函数） | 至到期后按对账留存 |
| 功能数据 | 关注、收藏、历史、关键词 / 名人监控、舆情跟进状态 | `follows`、`favorites`、`history`、`keyword_watches`、`opinion_event_status` | 仅创建者可读写 | 至删除 / 撤回 / 注销 |
| 配额与防滥用 | openid + 当日计数 | `refresh_quota`、`generate_quota`、`ask_quota`、`ai_calls`、`deep_dive_quota` | 本人可读不可写 / **客户端不可读写**（`ai_calls`） | 随「清空数据」/ 撤回 / 注销删除 |
| 行为统计 | openid + 事件名 + personKey + 参数 | `events` | 仅创建者可读写 | 同上 |
| 交易 | openid、金额、套餐、支付单号、状态 | `orders` | 本人可读不可写 | **不少于三年**（法定） |
| 售后 | openid、订单号、**用户填写的退款理由**、处理备注、退款金额 / 单号 | `refund_requests`（2026-10-22 新增） | **客户端不可读写**（仅云函数；用户经 `refundApply.my` 只看自己那几条） | 与 `orders` 同口径：注销时**去标识化后留存**（pending 申请对应一笔未退出的钱，且退款理由是财务凭据） |
| 生成锁 | `builder`（= userId，标记谁持有生成锁） | `report_cache` | 所有人可读、客户端不可写（写走 `aiProxy`） | 报告长期复用，不自动过期 |

**不含个人信息**的全局共享表（键为 personKey / 关键词哈希，内容为公开信息聚合，不指向用户）：
`report_cache`（除 `builder` 一列）、`feed_cache`、`hot_board`、`keywords`、`risk_scans`、
`risk_signals`、`opinion_events`、`person_assets`。

> 口径说明：上表「不含个人信息」是指**不能关联到具体用户**；这些表的内容本身是关于**公众人物**的
> 公开信息聚合，其合规风险（名誉权、公开信息处理范围）在 §五.4 单独评估。

**删除路径的一致性**（`src/utils/data-deletion.ts`）：清空数据 / 撤回同意 / 注销账号均删除
`follows`、`favorites`、`history`、`keyword_watches`、`events` 与本地缓存；
`risk_signals` / `risk_scans` 为 personKey 维度的共享扫描结果、**不含 openid**，
不在「我的数据」范围内，故不随之删除（此口径已在政策「保存期限」条中承诺）。
删除失败必须如实告知用户（逐条检查 `error`，不吞错），否则会出现「界面说清了、云端还在」。

## 四、第 56 条(二)：对个人权益的影响与安全风险

### 4.1 风险清单与缓解措施

| 风险 | 影响 | 已采取的措施 | 落实位置 / 证据 |
|---|---|---|---|
| 账号标识或功能数据被他人读取 | 隐私泄露 | 五张用户表均为「仅创建者可读写」；配额表与订单「本人可读、不可写」；`memberships` / `ai_calls` 客户端完全不可读写 | `cloudfunctions/dbInit/schema.js` 的 ACL；`dbInit` 比对真实库并补齐权限 |
| 会员身份被端上自证（改包白用） | 公平性 / 成本转嫁 | 权威值放在 `memberships`（客户端不可读写），云端判档一律读它；`users.membership` 降级为界面镜像 | `cloudfunctions/{payCallback,quotaGuard,aiProxy}` |
| 全局共享表被任意登录用户改写（投毒） | 内容完整性 / 二次传播错误信息 | 共享表客户端**只读**，写入一律走云函数 `aiProxy` 写口 | `schema.js` 中 `report_cache` / `feed_cache` 的 P0-2 注记 |
| 上游厂商拿到用户身份 | 对外提供扩大化 | 请求体不含 openid / 昵称 / 头像；只发送完成该次处理所必需的最少内容 | 政策「委托处理与最小化」条；`cloudfunctions/aiProxy` 组包处 |
| 备用检索源（境外）导致出境 | 跨境合规风险 | 默认不装配（key 留空）；启用前置条件见 §六 | `.env.example` 注释；`aiProxy#BACKUP_PROVIDERS` |
| 埋点过度采集 | 超出目的范围 | 事件名固定枚举，仅含 personKey 与轻量参数、不含自由文本；用途限定为成本与稳定性分析 | `schema.js#events`、政策「使用统计」条 |
| 删除不彻底 | 权利响应不真实 | 删除走统一函数并**逐条检查 error**；失败如实回报 | `src/utils/data-deletion.ts` |
| 机审 fail-open（服务端未配时放行） | 内容安全兜底失效 | 已明示为**已知取舍**：用户自由文本对外不可见，漏拦风险低于「服务不可用」；另有本地敏感拦截 + 提示词层拒答兜底 | `src/utils/sec-check.ts`、`src/utils/sensitive.ts`、`src/utils/{disambiguate,report}.ts` |
| 免费额度被改包绕过 | 成本 | 硬边界放在云端的 `ai_calls` 限速（端上不可写）；产品额度层**不声称**是安全边界 | `cloudfunctions/aiProxy`、CHANGELOG「每日上限也在服务端判」 |
| 内部超管越权查看 / 改动用户数据（2026-10-18 新增） | 隐私泄露 / 权利被绕过 | ① 鉴权在服务端：云函数 `adminConsole` 只认环境变量 `ADMIN_OPENIDS` 里的 openid，**未配置即全部拒绝**（fail-closed），端上的「是否超管」只是渲染开关；② 查询范围限于**账号与会员字段**（昵称 / openid / 注册与活跃时间 / 会员有效期 / 配额计数），不返回用户生成的正文（报告、问答、收藏的内容），也不提供「导出全表」；③ 改会员不新增写口，一律代理 `payCallback`，权威行留 `last_admin_op`（谁在哪天动了什么）；④ 模型厂商开关停机保护：不允许全停，避免"防故障的开关"本身变成全站故障 | `cloudfunctions/adminConsole/index.js`、`src/package/admin/*`、`cloudfunctions/payCallback/after-sales.js#adminRevokeMember`、`schema.js#sys_config` |
| AI 生成内容失真 / 侵犯名誉 | 第三方权益 | 结论均基于公开来源、逐条可溯源；提供纠错与下线入口；免责声明明确「仅供参考」 | 政策第四章；`src/pages/agreement` 的「名誉与纠错」 |

> **接收方范围（2026-10-14 核对）**：大模型接收方**不是固定的** ——「我的」页可在
> **腾讯云（云开发 AI，默认）**与 **DeepSeek / 智谱 GLM / Kimi / 通义千问 / 火山方舟** 之间切换
> （`src/config/public.ts#LLM_VENDORS` ↔ 云端 `cloudfunctions/aiProxy/llm.config.js#VENDORS`；
> 端上只上报厂商标识，连具体模型名都不上报）。六家**均属境内主体**，政策「第三方共享」条已逐家列明 ⇒ 现状不构成出境。

> 送去境外），**必须先把 §六 那四条前置条件做完**（政策跨境条款 + 单独同意 + 更新本记录 + 论证出境必要性）——

## 五、逐项说明（敏感、未成年人、自动化、公开信息）

1. **支付订单（从严按敏感处理）**：`orders` 客户端**不可写**、本人可读；金额由下单时的
   `PLANS` 白名单决定、回调金额必须与订单相等才发货，可防篡改；支付单号仅用于对账；
   按《电子商务法》留存不少于三年。
   **退款理由**（`refund_requests.reason`）是用户主动填写的自由文本：集合为**客户端不可读写**（仅云函数），
   只对**提交者本人**（经 `refundApply.my`）与**超管**（运维中心待办）可见；不进任何共享缓存、
   不参与 AI 生成与检索。用途唯一 —— 让核实退款的人知道要查什么，因此不做二次利用。
2. **未成年人**：本服务面向成年人，不主动、不专门面向不满 14 周岁儿童收集个人信息；
   已按第 31 条制定**专门的处理规则**（政策第三章），首次同意弹窗含「年龄 / 监护人同意」确认；
   监护人的权利行使入口与普通用户一致。
3. **自动化决策**：判定为「不触发」（见 §一）。仍保留两条自我约束：报告 / 舆情中的分级与排序
   只是**内容组织方式**，不对用户作出任何具有法律影响或显著影响的决定；用户不使用相应功能即可回避。
4. **公开个人信息的处理**：处理对象是**公众人物**的**公开信息**，未超出该信息被公开时的目的
   （第 27 条）；不加工成对特定自然人的负面结论用于牟利；设有「名誉与纠错」下线通道。
5. **不做的处理**：不做用户画像、不做定向推送、不做差别定价、不出售个人信息、不公开用户信息。

## 六、第 56 条(三)：保护措施是否合法、有效、与风险相适应

- **技术措施**：云开发文档型数据库（境内）+ 逐集合最小权限（`schema.js` 为单一事实源，
  由 `dbInit` 比对真实库并补齐）；敏感权威数据客户端完全不可读写；写口收敛到云函数；
  配额与限速取**服务端时间**、原子自增（防改设备时间 / 防伪造）；端上无直连上游通道。
- **管理措施**：政策版本化（改政策 = 用户重新同意，`config/legal.ts` → `consent.ts`）；
  本记录 + 处理情况记录留档不少于三年；七项权利均有端上入口，其中同意 / 撤回 / 清空 / 注销 / 导出
  五条链路由用例钉住（`test/cases/{02-data,41-consent,42-data-export}.js`；**注销**这条横跨两个文件：
  `41-consent.js` 钉入口 / 二次确认 / 善后只清本机，`18-user-config.js` 钉云端「删净且只删自己的 /
  订单去标识化保留 / 失败不中止 / 幂等 / 无 OPENID 拒绝」，并钉住删表清单与 `dbInit/schema.js` 对齐
  —— 日后新增带用户标识的集合而忘了加进删表清单时，用例会直接失败）。
- **相适应的结论**：在**不出境、不处理用户敏感信息、不做自动化决策**的现状下，
  残余风险主要落在「上游厂商接收公开检索内容」与「公众人物名誉」两项，均已通过
  最小化 + 可溯源 + 纠错通道压到可接受程度。

### ⚠ 启用境外备用检索源的前置条件（未完成前不得填入 key）

1. 隐私政策增列**跨境条款**（境外接收方名称、处理目的、处理方式、个人信息种类），并保留
   「如实变更则另行取得单独同意」的承诺；
2. 端上就「向境外提供个人信息」取得**单独同意**（PIPL 第 39 条），与其他同意**分开**、可随时撤回；
3. 更新**本记录**（新增出境评估一节），并按第 56 条继续留档三年；
4. 论证「公开检索词可能含自然人姓名」的出境必要性 —— 若无法通过，应改用境内第二检索源
   或保持仅博查。

> 现状（2026-10-14）：`SERPER_API_KEY` / `TAVILY_API_KEY` 均留空，数据全程境内，
> 与政策「存储地域」条的披露口径一致。

## 七、结论与待办

- **结论**：现状下的处理活动**合法、正当、必要**，风险与保护措施相适应，可以继续开展。
- **待办（不完成则本记录不完整）**：
  1. 处理者身份：**已按「个人开发者（自然人）」口径写明**，与政策「处理者与联系方式」条一致 ——
     政策原文为「本小程序由个人开发者独立运营。涉及个人信息的问题或权利请求，可通过
     『我的 → 内容举报 / 反馈』与我们联系」，且该渠道**就是**端上唯一能收件的入口（微信客服会话）。
     ⚠ 两点如实说明：① **个人开发者属自然人主体，本无统一社会信用代码**，不得为「填满字段」而编造；
     ② 现未在政策里披露开发者真实姓名 / 邮箱。若你愿意进一步披露（更透明，但等于公开个人身份），
     改政策文案即可；**若日后变更为企业主体，须同时更新政策与本记录**（政策实质变更 → 触发重新同意）。
  2. 若启用境外备用检索源，先完成 §六 四条前置条件；
  3. 数据类别、接收方或政策版本任一变更时，**同步更新本记录**并调整 `config/legal.ts` 日期
     （该日期是同意版本号，改动即触发重新征求同意）。
- **复审触发点**：新增个人数据类别 / 新增上游接收方 / 启用跨境 / 主体信息变更 /
  政策实质变更 / 发生个人信息安全事件。
