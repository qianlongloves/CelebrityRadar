# 个人信息保护影响评估（PIPIA）

> 依据《中华人民共和国个人信息保护法》（下称「PIPL」）第 55、56 条编制。
> 本文件是「名人雷达」微信小程序的个人信息保护影响评估记录，依法保存。

## 一、处理活动与数据清单

### 1.1 我们收集与处理的个人信息

| 类别 | 具体内容 | 存储位置（云开发集合） | 证据真源 |
| --- | --- | --- | --- |
| 账号标识 | 微信匿名标识 `openid`（唯一标识，不结合手机号/位置等） | 见下方各集合 | `src/pages/agreement/index.tsx`「自动登录」条 |
| 用户资料 | 昵称、头像（用户主动设置，可修改） | `users` | 同上；`src/stores/auth.ts` |
| 功能数据 | 关注、收藏、浏览历史、关键词订阅、名人监控、舆情跟进状态 | `follows` / `favorites` / `history` / `keyword_watches` / `opinion_event_status` | `cloudfunctions/dbInit/schema.js` |
| 偏好设置 | 生成偏好：厂商 `llm_provider`、质量档 `llm_tier`（两项，可置空） | `users.settings` | `src/config/user-defaults.ts` |
| 交易记录 | 会员订单与退款（依法留存，不少于三年） | `orders` | `cloudfunctions/dbInit/schema.js`「orders」 |
| 使用统计 | 功能计数与限速计数（生成次数、提问次数、刷新次数、防滥用计数、埋点） | `generate_quota` / `ask_quota` / `refresh_quota` / `ai_calls` / `events` | `cloudfunctions/dbInit/schema.js` |

**不收集**：手机号、位置、通讯录、麦克风、相册（除用户主动保存分享图）、生物识别、金融账户、行踪轨迹等。见 `src/pages/agreement/index.tsx`「我们不做的事」条。

### 1.2 全局共享数据（不属于任何个人，不按人落库）

报告缓存 `report_cache`（主键 `personKey = 名字#领域码`）、热门榜 `hot_board`、检索结果映射 `feed_cache`、关键词检索缓存 `keywords`、风险扫描 `risk_scans` / `risk_signals`、舆情事件 `opinion_events`、人物素材 `person_assets` 等：**均为公开名人信息的聚合产物，不含用户账号标识，客户端只读**。证据：`cloudfunctions/dbInit/schema.js` 各集合 `purpose` 字段。

### 1.3 处理活动

| 处理活动 | 处理方式 | 委托/接收方 | 地域 |
| --- | --- | --- | --- |
| 自动登录 | 微信登录能力换取 `openid` | 微信开放平台 | 境内 |
| 联网检索 | 发送**公开检索词**（人名/关键词） | 主源博查；备用源 SERPER / TAVILY（**默认关闭**） | 主源境内；备用源境外 |
| 内容生成 | 公开检索词/网页内容 + 用户主动输入的问题原文 | 默认腾讯云（微信云开发 AI，`cloud.ai` 零 key）；可选 DeepSeek / 智谱 GLM / Kimi / 通义千问 / 火山方舟（OpenAI 兼容直连，key 只存云函数环境变量） | 境内（六家厂商均在境内） |

证据：`cloudfunctions/aiProxy/index.js`（检索源常量 `BOCHA_ENDPOINT` / `SERPER_ENDPOINT` / `TAVILY_ENDPOINT`、`BACKUP_PROVIDERS`；大模型通道 cloudai + http 两通道）、`cloudfunctions/aiProxy/llm.config.js`（`VENDORS` 六家厂商注册表、`channel` 两通道、`DEFAULT_VENDOR='cloudbase'`）。

## 二、第 55 条触发情形逐项判定

PIPL 第 55 条列举的五类「应当事前进行 PIPIA」的情形，逐项判定如下：

| 情形 | 是否触发 | 判定依据 |
| --- | --- | --- |
| （一）处理敏感个人信息 | **否** | 不收集手机号、位置、通讯录、生物识别、金融账户、行踪轨迹等；`openid` 为匿名标识且不与其他信息结合识别到自然人。见 `src/pages/agreement/index.tsx`「自动登录 / 我们不做的事」条。 |
| （二）利用个人信息进行自动化决策 | **否** | 报告、榜单、舆情事件为算法基于**公开信息**生成，仅供参考、不对用户本人作出有法律/显著影响的决定。见「自动化处理说明」条。 |
| （三）委托处理 / 向其他处理者提供 / 公开个人信息 | **是** | 存在委托处理：联网检索、内容生成、微信支付、微信云开发。见「第三方共享 / 委托处理与最小化」条。 |
| （四）向境外提供个人信息 | **现状否（默认）** | 境外备用检索源 SERPER / TAVILY 默认关闭；启用时仅发送公开检索词、不含账号标识（详见第六节）。见 `.env.example` 对应注释。 |
| （五）其他对个人权益有重大影响的处理 | **否** | 未发现画像、营销、监控等重大影响活动。 |

**结论：因第（三）项「委托处理」触发，须进行本评估；且第（四）项在「启用境外备用检索源」时为新增触发情形（见第六节）。**

## 三、第 56 条三项评估

### 3.1 处理目的、处理方式是否合法、正当、必要

**合法**：处理基于用户对《隐私与免责声明》的**知情同意**（首次进入弹窗征求、同意结果连同版本号落本机，政策更新自动重新征求同意），符合 PIPL 第 13 条「取得个人同意」；对不满 14 周岁未成年人设有专门规则与监护人同意（第 31 条）。证据：`src/utils/consent.ts`、`src/components/consent-gate/`、`src/components/privacy-gate/`、`src/pages/agreement/index.tsx` 第三章。

**正当**：仅用于「提供关注/收藏/历史/监控、生成名人报告、会员服务、成本与稳定性统计」，不用于用户画像与营销。见「使用统计 / 自动化处理说明」条。

**必要（最小化）**：
- 账号标识只在**境内云函数内**用于判断会员身份与额度，不随请求发往任何厂商——「每次请求只发必需的最少内容，不含账号标识与昵称/头像」。见「委托处理与最小化」条。
- 端上不持任何厂商密钥、不知道模型名，请求只带「厂商 + 质量档」（`vendor` / `quality`），具体模型由云端注册表按「厂商 × 档 × 能力槽」裁决。证据：`src/config/public.ts`（`llm.vendors` / `llm.qualities`，无任何 key / 端点 / 模型名）、`src/utils/llm.ts#resolveChatSelection`。
- 内容生成默认走腾讯云（微信云开发 AI，`cloud.ai` 零 key）；其余 DeepSeek / 智谱 GLM / Kimi / 通义千问 / 火山方舟均为**境内**厂商，key 只存云函数环境变量、绝不进小程序包。证据：`cloudfunctions/aiProxy/llm.config.js`。
- AI 提问的问题原文仅随该次请求转发用于生成、**不写入用户数据库**。见「第三方共享」条。

### 3.2 对个人权益的影响及安全风险

| 影响 / 风险 | 评估 | 说明与证据 |
| --- | --- | --- |
| 信息泄露 | **低** | 不收集敏感信息；端上不持凭据；委托请求不含账号标识；账号标识只在境内云函数内使用。 |
| 越权访问他人数据 | **低** | 个人集合权限为「仅创建者可读写」；云端身份只认 `getWXContext().OPENID`，不认端上行；会员/额度读服务端权威表 `memberships`，不读端上可改的 `users.membership`。证据：`cloudfunctions/aiProxy/index.js` `isActiveMember`、`quotaGate`。 |
| 缓存串味 / 伪造共享缓存 | **低** | 报告/榜单为全局共享缓存、客户端只读，写入走云函数；人物素材只收 `personKey`、不接受客户端 URL。证据：`cloudfunctions/dbInit/schema.js`、`cloudfunctions/aiProxy/index.js` `handlePortrait`。 |
| 自动化决策风险 | **无** | 不对用户本人作决策。 |
| 未成年人风险 | **低** | 设有专门规则与监护人同意确认，发现未取得监护人同意即删除。 |
| 权利行使受阻 | **低** | 提供查阅、复制（导出 JSON）、更正、删除、撤回同意、注销账号六项权利，入口齐全。证据：`src/utils/data-export.ts`、`src/utils/data-deletion.ts`、`cloudfunctions/userInit/index.js#deleteAccount`、`src/pages/mine/index.tsx`。 |

### 3.3 保护措施是否合法、有效并与风险程度相适应

- **数据最小化与隔离**：委托请求剥离账号标识；全局缓存与个人数据分库分权限；问题原文不落库。
- **访问控制**：个人集合「仅创建者可读写」；云端身份只认 `OPENID`。
- **服务端权威**：会员与额度以 `memberships` 为唯一权威，杜绝端上自证。
- **删除权落地**：`userInit.deleteAccount` 删除本人全部个人数据、订单去标识化保留（依法留存），删表清单与 `schema.js` 对齐（日后新增带用户标识的集合会因测试失败被拦下）。证据：`cloudfunctions/userInit/index.js`、`test/cases/18-user-config.js`。
- **文本卫生**：入库文本统一净化与截断。证据：`src/utils/text.ts`。
- **跨境默认关闭**：境外备用检索源默认不启用（见第六节）。

上述措施与「低敏感、不画像、不作决策」的风险水平相适应。

## 四、评估结论

在**现状**（不向境外提供个人信息、不处理敏感个人信息、不作自动化决策）下，本项目对个人权益的影响与安全风险**可控**，处理活动合法、正当、必要，保护措施与风险程度相适应。

## 五、保存与更新

1. 本评估报告与处理情况记录依法**保存不少于三年**。
2. 以下情形须**同步更新本文件**（并同步评估是否须重新取得用户同意）：
   - 数据类别变化（新增/删除个人信息字段或集合）；
   - 委托/接收方变化（增删服务商、切换大模型或检索源）；
   - 隐私政策版本变化（`src/config/legal.ts` 的生效日期）；
   - 启用境外备用检索源（见第六节，属新增触发情形）。

## 六、启用境外备用检索源的前置条件清单

现状下境外备用检索源（SERPER / TAVILY）**默认关闭**，数据全程在境内。若确需启用，构成「向境外提供个人信息」风险场景（PIPL 第 38、39 条），启用前**必须逐项完成**：

1. **更新隐私政策**：在「存储地域 / 第三方共享」条如实增列跨境条款，写明境外接收方名称、国别、传输内容与目的，并更新 `src/config/legal.ts` 生效日期（= 触发重新征求同意）。
2. **端上单独同意**：对跨境传输取得用户的**单独同意**（PIPL 第 39 条），不能仅靠首次整体同意覆盖。
3. **论证出境必要性**：形成书面记录，说明为何境内主源（博查）不足以完成该次检索、确需启用境外备用源，并写明「仅发送公开检索词、不含账号标识」的技术约束（证据：`cloudfunctions/aiProxy/index.js` 的 `BACKUP_PROVIDERS` 与检索词构造）。
4. **更新本评估**：回到第二节第（四）项，将「是否触发」改为「是」，并按第六节说明补记跨境专项评估与第 56 条三项的更新结论。
5. **落盘留档**：完成以上步骤后，方可在 `cloudfunctions/aiProxy` 环境变量填入 `SERPER_API_KEY` / `TAVILY_API_KEY`（`.env.example` 注释已指向本节）。

> 前置条件未全部满足前，**不得**配置境外检索源的 key；部署后可用云函数运维探针验证连通性（`exports.main` 中 `action === 'test'` 分支的 `probeBackup`，见 `cloudfunctions/aiProxy/index.js`）。
